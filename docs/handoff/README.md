# 用 AI 维护享玩

项目：<https://github.com/wzyhn/xiangwanai>。本仓库包含完整的小程序、运营后台、API、worker、独立数据库迁移和部署文件。你可以修改整个享玩项目；发行支持、共享依赖和 workflow 也可以在本仓库内修改并验证。它们不会自动改写私有平台的共享实现。

## 第一次使用

1. 在电脑安装能读写本地文件、运行命令的 AI 编程工具，用自己的 GitHub 账号登录。只使用聊天网页的 AI 通常不能替你运行项目。
2. 解压交接包到一个独立目录。把 [首次启动提示词](01-start.md) 全部复制给 AI，并告诉它解压路径。
3. 私下交接包内 `private/mcp.json` 是服务器连接凭据，供 AI 从本地文件读取；这里公开的 [mcp.example.json](mcp.example.json) 只有占位符。不要将真实配置粘贴进聊天、提交到 Git 或上传公共附件。
4. 告诉 AI 你的需求和可观察的完成标准，使用 [日常修改提示词](02-change.md)。修改完成后得到 PR、测试结果和可检查的页面。
5. 发布到服务器时使用 [部署提示词](03-deploy.md)。如果希望同时回到原平台，由有私有仓库权限的维护者执行 [平台集成提示词](04-platform-sync.md)。

你通常只需要登录 GitHub、说明需求、查看页面效果，以及在第一次需要小程序权限时用自己的微信开发者账号登录。GitHub 写权限、微信开发者身份和 MCP 是三套独立权限，压缩包不会替你登录 GitHub 或微信。

## 代码如何流转

```text
你的需求 → AI 修改自己的分支 → 本地验证 → 公开 PR → CI 通过 → 合并 main
                                                      ↓
                                 构建、发布享玩服务器、检查运行结果
                                                      ↓
                             维护者另行生成并接受私有平台集成 PR
```

公开 main、私有平台 main 和服务器运行镜像是三个不同位置。当前没有启用公开仓库到私有平台的定时同步；公开 CI 只检查和构建，不推送生产镜像，不会自动部署。不能用“合并了”代替“上线了”。

外部贡献者可以先 Fork，不需要私有平台访问权限。若维护者给了公开仓库 write 权限，可以直接在上游建立分支和 PR；main 通过检查后可以合并。没有 write 权限时，在自己的 Fork 修改并提交上游 PR。涉及无法完成的账号授权，AI 应只报告具体缺少的身份和操作，不能索要整个平台账号。

## 常用位置

| 要改什么 | 首先阅读 |
| --- | --- |
| 首页、头像、报名、问卷、支付页面、底部导航 | `apps/miniprogram-xiangwan/README.md`、对应页面和 feature |
| 后台页面、表单、预览 | `apps/xiangwan-admin-web/README.md`、`src/app` 与 `src/lib` |
| 报名/订单/退款/活动规则、权限、持久化 | `internal/domains/xiangwan`、`cmd/xiangwan` |
| 数据表 | `deploy/sql/manifest.json` 与产品迁移；已有 SQL 不改写 |
| 独立部署 | `deploy/xiangwan/README.md`、`Dockerfile` |
| 故障定位 | [检查命令与常见问题](05-operations.md) |

服务器现有资源和配置可能早于公开仓库，发布前须读取实际镜像、挂载和数据库状态。独立迁移器只适用于自己的新独立库；现有生产库继续遵守原迁移体系。源码包可以独立构建，不等于已有生产库可以随意重建。
