# 享玩 AI 人工退款操作规则

V1 只在微信商户平台或客户认可的原支付渠道人工退款。享玩后台记录退款单的处理进度和外部结果，不向渠道发起退款。订单实付金额和外部渠道记录是金额核对依据；报名取消不等于款项已退。

1. 具有租户级 `finance` 权限的财务人员领取 `pending_manual` 或 `failed` 退款单，核对报名、订单实付和应退金额后标记为 `processing`。每次重试使用新的操作键。
2. 财务人员在外部渠道办理退款。若渠道失败或无法核实，登记具体失败原因，退款单进入 `failed`；这不恢复报名资格。`failed` 可重新领取。
3. 渠道显示最终退款成功后，由**另一名**具有租户级 `super_admin` 权限的人员在渠道核对退款单号、成功金额、成功时间和官方记录，再在享玩后台登记 `refunded`。必须同时填写外部退款单号和可复查的官方记录引用；截图、口头说明或“处理中”状态单独不能作为完成凭证。成功金额必须等于退款单应退金额，且不超过订单实付金额。
4. `rejected` 只用于有明确业务依据、确实无需退款的异常单，由超级管理员填写原因后登记。普通渠道失败必须使用 `failed`，不能以 `rejected` 隐藏待退款。
5. 每个状态写入都使用操作键、版本围栏和不可变事件；网络结果未知时复用原键查询/重试。后台仅在服务端持久化结果返回后展示成功。财务与超级管理员权限在同一数据库写事务中复核，处理人和最终确认人必须是两个不同账号。

上线前仍需客户给出商户平台账号、首位财务与超级管理员的实名分配、退款时限和日对账责任人；这些外部资产不由测试结果替代。
