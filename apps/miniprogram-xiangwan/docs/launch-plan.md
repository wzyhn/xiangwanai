# 享玩 AI 小程序｜顺序交付计划

所有步骤只在唯一 Xiangwan worktree 内按 PR 顺序执行：代码与测试 → 提交 PR → `@codex review` → 下一 PR；最终统一修 Review 并通过 merge gate。

| 阶段    | 范围                                                                | 状态                         | 合并条件                                                                                                                    |
| ------- | ------------------------------------------------------------------- | ---------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| FE-1    | 产品身份、独立 Runtime boot、活动列表、单场详情、免费报名、报名状态 | 代码完成                     | Xiangwan 测试、docs、主题与 release fail-closed 检查通过；AppID 已写入项目配置，真机/体验版仍等待 AppSecret、合法域名和验收 |
| FE-2    | 消费者签到二维码、备份码、过期/刷新/后台清密                        | 代码完成                     | QR 编解码验证通过；token 不持久化                                                                                           |
| FE-3    | 现场扫码 UI                                                         | 阻断                         | 先有独立 staff auth/on-site grant 后端边界                                                                                  |
| FE-4    | 本人订单列表/详情；微信支付、商户查单和失败恢复                     | 客户端代码完成；真实支付阻断 | 精确订单版本/金额与服务端能力门控、同一预支付操作键恢复、弹窗后服务端查单已测试；支付仍需商户资产、签名、真机与资金回归     |
| FE-5    | 本人取消、退款状态；往期活动、优惠券与收藏                          | 代码完成                     | 空 POST、服务端门控、未知结果刷新与分轴状态通过；优惠券只读且服务端裁决；收藏绑定 Series、取消后重读，多场次显式选择        |
| FE-6    | 公开社区人物；本人身份、角色、主理人申请与贡献只读视图              | 代码完成                     | PeopleProfile 仅审核发布且精确路由；MyBenefits 当前 Principal 快照分轴展示，不推断绑定、不提供身份写入或申请动作            |
| Release | 客户 AppID/域名/法务/微信隐私/运维/真机                             | 外部阻断                     | workflow 对不可变 main 提交执行 `check:release` 且全绿                                                                      |

FE-1 只有在服务端明确宣告微信支付可用时才创建付费订单；FE-2 不会顺带开放工作人员扫码权限；Release 不会使用中央 Weconq 域名或其他产品 AppID 兜底。
